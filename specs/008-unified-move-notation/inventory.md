# Move notation implementation inventory

Status: source audit, 2026-11-15. This is evidence for an architecture proposal, not implementation approval. Paths below are relative to the named repository; SHAs pin the inspected committed sources. Coverage references identify existing tests, not tests run for this inventory. An untracked `scratch_mod.bak` in Cubacle was excluded.

## Existing decisions

PuzlWerk `specs/006-shared-model/plan.md` L7 and SM9 decide the PuzlWerk move AST as the sole semantic target and dialects as adapters with token-to-AST vectors. SM1 selects wire-v1 semantics; SM7 directs Picture Cube 4–7 to PuzlWerk core and certification, rather than a separate NxN engine. `specs/001-core-foundation/research.md` Q2 bounds the core text parser to outer faces and wide moves, without aliases, slices or rotations; the AST remains complete. These decisions are not reopened here.

## Persistence, compatibility and provenance

CubeLab `src/client/store.ts` reads and writes a `dialect` URL parameter; `src/client/notation-dialect.ts:dialectForAlgorithmInput` selects unambiguous Jaap or SSE spellings without changing the saved dialect. `MoveTypes.res` distinguishes dialect and lowercase interpretation, so legacy strings cannot safely be converted without their source context. CubeLab `src/Move/MoveParser.res` accepts ordinary middle slices on sizes 3 and 5, while `docs/move-notation-compatibility.md` says 3 only; code and documentation conflict and must be reconciled before relying on either as a compatibility claim. CubeLab's compatibility report and ACube documentation are `docs/move-notation-compatibility.md` and `docs/acube-notation.md`. Historical saved strings and share links need preservation and explicit version/dialect handling; this inventory does not establish all persistence locations.

CubeLab and Cubistry mechanics declare AGPL-3.0-or-later in their package metadata; Cubacle declares the same in `Cargo.toml`. PuzlWerk `specs/006-shared-model/plan.md` SM11 records the EUPL-1.2 core decision and says the core license file is not yet written; private solver packages retain their own licenses and provenance. Moving or copying CubeLab code across those boundaries requires a specific license and provenance review, not an assumption that ReScript modules can be extracted freely. The intended direction in PuzlWerk `README.md` is core to viewer to applications, with no reverse dependency; a CubeLab-owned implementation imported by core would invert it.

## Evidence gaps

No test suite was run to produce this inventory. Existing test names show intended coverage only; they do not prove current pass status or semantic equivalence between implementations. Full saved-algorithm stores, share-link variants, CubeAssembler integration, extension runtime and every solver/display consumer require further tracing before migration. Parser size 6–7, round-trip execution across implementations, generated TypeScript safety and license compatibility are UNKNOWN until separately demonstrated.
