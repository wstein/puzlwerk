# Appearance schema v1: `puzlwerk.appearance`

Status: Proposed. The shape (a separate document per sticker ID, wire-v1 revision 1 unchanged) is owner decision SM3 of 2026-11-12 ([plan](../../006-shared-model/plan.md), [#47](https://github.com/wstein/puzlwerk/issues/47)). The field rules below are proposals until the owner accepts [ADR 0009](../../../docs/adr/0009-appearance-document.md). Reference reader and vectors: `test/helpers/appearance-reference.mjs`, `test/fixtures/appearance/`, generated by `scripts/appearance-examples.mjs`.

## Scope

The document says how stickers of a [wire-v1](wire-v1.md) definition look: a color token, an image reference and the design symmetry of the picture. It is not part of the definition or the state, so it never changes identity, positions, poses or hashes of those documents. Image bytes, crops, resolution, materials and rendering stay in the application.

## Canonical bytes

As in wire-v1: UTF-8 JSON without insignificant whitespace, keys sorted by code unit, integers only, no duplicate keys, `stickers` sorted by `id`; the decoder accepts any whitespace and array order and re-encodes canonically. All strings are IDs. A hash is `sha256:` plus the lowercase hex SHA-256 of the canonical bytes.

## Document

Closed object; unknown fields are errors.

- `schema`: `"puzlwerk.appearance"`; `revision`: `1` (other integers: `BadRevision`).
- `id`: ID of this document; `definitionId`: ID of the wire-v1 definition it belongs to.
- `imageIds`: optional; the only value is `"tile-v1"` (below). Absent means image references are opaque.
- `stickers`: array of entries, at most one per sticker, in any order. Stickers without an entry have no appearance information; a consumer falls back to the `color` of the definition and then to its own default.

Entry: closed object with `id` (ID of a sticker of the definition) and at least one of:

- `color`: ID of a color token. The palette (token to RGB, material, scheme) belongs to the application. A color here overrides the optional `color` of the definition for display; it is never compared with it and never an identity.
- `image`: ID of an image, 1 to 256 characters (the Cubacle limit). The application resolves it to bytes and crop. The image is upright with respect to the `up` vector of the sticker in the definition, so it turns with the sticker.
- `symmetry`: `"C1"`, `"C2"` or `"C4"`: the quarter turns about the sticker normal under which the picture looks the same are `{0}`, `{0,2}` or `{0,1,2,3}` (data model, "Goal symmetry"; the period naming of ADR 0008 item 6 is the inverse). Absent means `C1`. It declares what the picture looks like; a goal may still demand more, and no goal can claim more than this declaration.

## Tile ID rule (`tile-v1`)

With `imageIds` `"tile-v1"`, every entry has an `image` equal to `<face>_<row>_<col>` computed from the definition: `face` is the letter of the sticker normal (`U` +Y, `D` -Y, `F` +Z, `B` -Z, `R` +X, `L` -X); with `home` the doubled home slot of the piece, `n` the size, `right = up x normal` and `up` the sticker `up`: `col = (home . right + n - 1) / 2` and `row = (n - 1 - home . up) / 2`. Row 0 is the top and column 0 the left of the face seen from outside. It reproduces the Cubistry tile IDs `F_<row>_<col>` (`sliceFaceSet`, `facePosition`) for size 3 (all 54 cells, vectors) and size 2 (by hand); sizes 4 to 7 follow the same formula and are not checked against Cubistry. The tile belongs to the home position of the sticker, so the picture travels with the sticker.

## Errors

Same shape as wire-v1: stable code and JSON path of the first offending value. Codes shared with wire-v1: `WrongType`, `MissingField`, `UnknownField`, `BadSchema`, `BadRevision`, `BadId`, `BadValue`, `DuplicateId`, `DefinitionMismatch`. New: `StickerMismatch` (entry `id` is no sticker of the definition), `BadSymmetry` (not `C1`, `C2`, `C4`), `BadTile` (`tile-v1` and the entry has no `image` or another one than the rule gives). `BadValue` also covers an entry with only an `id` and an unknown `imageIds`.

| Source | Maps to |
| --- | --- |
| Cubistry `cubistry.print` sticker `assetId` | `image`; `equivalentQuarterTurns` `[0]`, `[0,2]`, `[0,1,2,3]` to `C1`, `C2`, `C4` (other sets are not a group and have no mapping); `materialId` stays in the application. |
| Cubistry Picture Cube (Playground 2 to 7, `FaceSet`) | `imageIds` `"tile-v1"`; the asset ID is the tile ID; face art and crops stay in the `FaceSet`. |
| Cubistry Calendar7 scheme Rubik-Tint | `color` per sticker from the home face; the darker weekend ground is derived by the application from the token. |
| Cubacle fixed-frame sticker `image: Option<String>` | `image` after mapping its characters to the ID alphabet; its `up` is the sticker `up`. |
